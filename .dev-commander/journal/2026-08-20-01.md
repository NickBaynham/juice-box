# 2026-08-20 entry 01

W1 persistence is complete: seven entities across five Alembic migrations, an async engine and session factory, an integration test harness, and six repository classes, all on main with CI green. Plan 0002 was scanned before implementation rather than after, which found seven blockers, five of them proven non-executable in a throwaway project: Alembic autogenerate would have emitted an empty migration because nothing imported the models, native enum types would have broken the mandated downgrade and re-upgrade cycle permanently on the persistent volume, the migration test would have left every later test file without a schema, a pooled engine fails on the second async test under asyncio_mode auto, and Alembic's stock template fails this project's lint so no generated revision could have been committed. Two increments were merged because they were mutually dependent, one was added to ship migrations in the container image, and the repository increment was split. Twenty-two corrections were recorded in the plan rather than applied silently. The workstream's recurring defect was tests that passed for the wrong reason: six of them, each by a different mechanism, ending with an implementer reporting three ordering tests as discriminating when one could not fail at all. Two rules now sit in the plan's global constraints as a result. The user decided mid-workstream to unify status values on lowercase across every entity, retrofitting agent and run through a hand-written data migration; that decision is ADR-0009. Review 0004 records the implementation review and carries six minors into W2 and W3. Four design documents still describe things that are not true, including design 0002's acceptance criterion and ADR-0001's CI service container.
