# Plan 0002: W1 Persistence

## Goal

Persist every Juice Box entity in PostgreSQL through async SQLAlchemy
with Alembic migrations, so state survives process death as ADR-0002
requires.

## Architecture

One async engine and session factory built from settings. Declarative
models in `persistence/models.py`, one autogenerated migration per model
increment, and async repository functions that own every query. No other
layer issues SQL or holds a session.

## Tech Stack

Plan 0001's stack plus SQLAlchemy 2.x with asyncio, asyncpg, Alembic.

## Global Constraints

- Definition of done: design 0002.
- Consumes ADR-0001 (PostgreSQL from the first increment), ADR-0002
  (durable state), ADR-0006 (agent id is the handle, runs are attempts).
- Every table has `created_at` as `TIMESTAMPTZ` defaulting to now.
  Mutable tables also have `updated_at`.
- Primary keys are `uuid4` UUID columns. Structured columns are `JSONB`.
- Model tests are integration tests; they run against Compose PostgreSQL.
- Requires W0 complete.

## Increments

### 1. Async engine and session factory

- [ ] Open and close async sessions against the configured database.

Files: `src/juicebox/persistence/__init__.py`,
`src/juicebox/persistence/database.py`,
`tests/integration/test_database.py`

Failing test first: `session_scope()` yields a session where
`await session.scalar(text("SELECT 1"))` returns 1; a second test asserts
that an exception raised inside the context manager rolls back and
propagates.

Minimal implementation: `create_async_engine(settings.database_url,
pool_pre_ping=True)`, an `async_sessionmaker` with
`expire_on_commit=False`, `Base(DeclarativeBase)`, and an
`asynccontextmanager` `session_scope()` that commits on clean exit and
rolls back on exception. Move `asyncpg>=0.30` to project dependencies and
add `sqlalchemy[asyncio]>=2.0`.

Verify: `pdm run pytest -m integration tests/integration/test_database.py`

Commit: `Add async engine and session factory`

### 2. Alembic migrations

- [ ] Apply and roll back schema migrations against the database.

Files: `alembic.ini`, `migrations/env.py`, `migrations/script.py.mako`,
`migrations/versions/.gitkeep`, `tests/integration/test_migrations.py`

Failing test first: run `alembic upgrade head` as a subprocess, assert
exit code 0 and that `alembic_version` holds exactly one row; run
`alembic downgrade base` and assert no application tables remain in
`information_schema.tables`.

Minimal implementation: `pdm add alembic`, then `alembic init -t async
migrations`. Edit `migrations/env.py` to take the URL from
`Settings().database_url` rather than `alembic.ini`, and to set
`target_metadata = Base.metadata`. Leave `sqlalchemy.url` empty in
`alembic.ini` so the database URL is never committed.

Verify: `pdm run pytest -m integration tests/integration/test_migrations.py`

Commit: `Wire Alembic for async migrations`

### 3. Agent and Run models

- [ ] Store agents and their run attempts.

Files: `src/juicebox/persistence/models.py`,
`migrations/versions/<hash>_add_agent_and_run.py`,
`tests/integration/test_models_agent.py`

Failing test first: insert an `Agent` with a definition and objective as
dicts, read it back in a new session, and assert the JSON round-trips and
`status` defaults to `AgentStatus.CREATED`. A second test inserts two
`Run` rows with the same `agent_id` and `attempt` and asserts
`IntegrityError`.

Minimal implementation: `AgentStatus` and `RunStatus` as Python enums
holding the eight section 6 states. `Agent` with `id`, `name`,
`definition`, `objective`, `repository_url`, `base_branch`,
`work_branch`, `status`, `failure_reason`, `created_at`, `updated_at`,
`started_at`, `finished_at`. `Run` with `id`, `agent_id` foreign key with
`ondelete="CASCADE"`, `attempt`, `status`, `iteration_count`,
`failure_reason`, `started_at`, `finished_at`, `created_at`, and a unique
constraint on `(agent_id, attempt)`. Generate the migration with
`alembic revision --autogenerate`.

Verify: `pdm run pytest -m integration tests/integration/test_models_agent.py`

Commit: `Add agent and run models`

### 4. Task model

### 7. Repository layer

- [ ] Provide the async accessors every other layer uses instead of SQL.

Files: `src/juicebox/persistence/repositories.py`,
`tests/integration/test_repositories.py`

Failing test first: `AgentRepository.create` returns an agent with an id;
`get` returns it and returns `None` for an unknown id; `list` returns
newest first and honours limit and offset; `set_status` persists the new
status and advances `updated_at`; `delete` removes the agent and cascades
to its runs and tasks.

Minimal implementation: `AgentRepository` with `create`, `get`, `list`,
`delete`, and `set_status`; `RunRepository` with `create_attempt`
computing the next attempt number, and `get_current`; `TaskRepository`,
`MessageRepository` with `list_unconsumed` and `mark_consumed`,
`EventRepository` with `append` and `list_for_agent`, and
`IterationRepository` with `append` and `list_for_run`. Each takes an
`AsyncSession`; none opens its own.

Verify: `pdm run pytest -m integration tests/integration/test_repositories.py`

Commit: `Add repository layer`

## Exit Criteria

Design 0002's workstream criteria, plus: migrations apply to an empty
database and roll back cleanly; every model round-trips through a
session; the repository layer is the only module issuing queries.
